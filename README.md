# Restaurant Review Platform — IFQ636 Assignment 2

A full-stack restaurant review platform (Node.js · Express · MongoDB · React) that
lets diners discover restaurants and post star-rated reviews, owners respond to
feedback, and administrators curate the catalogue and moderate content.

This repository is the **Assignment 2** project: it extends the Assignment 1
application by re-architecting the backend around **object-oriented design and
eight design patterns**, adding a new **in-app Notifications** subsystem,
expanding **automated unit testing**, and automating **build/test/deployment**
with a GitHub Actions **CI/CD** pipeline to AWS EC2 (nginx + pm2).

- **Public URL:** `http://<EC2_PUBLIC_IP>/`  ·  API: `http://<EC2_PUBLIC_IP>/api`  _(fill in after deploy)_
- **Demo logins:** `admin@mesa.test / admin1234` · `diner@mesa.test / diner1234`

---

## Features
- JWT-secured auth with roles (**diner** / **admin**); bcrypt password hashing.
- Browse / search (name, cuisine, location) / filter (min rating) / sort (rating, newest, name) with pagination.
- Reviews: full CRUD by the author; **one review per diner per restaurant** (DB unique index → HTTP 409).
- Auto-recomputed `averageRating` / `reviewCount` after every review change.
- Admin: restaurant CRUD (cascade delete of reviews) and review moderation; owner response to reviews.
- **In-app Notifications** generated by domain events (review published, owner response, moderator removal) — bell + dropdown in the UI.

## Architecture & design patterns
See `docs/A2/diagrams/architecture.png`. Eight patterns are implemented and unit-tested:

| Pattern | Where |
|---|---|
| Singleton | `backend/core/Logger.js`, `backend/core/Database.js` |
| Factory Method | `backend/factories/NotificationFactory.js` |
| Builder | `backend/builders/RestaurantQueryBuilder.js` |
| Repository | `backend/repositories/BaseRepository.js` (+ concrete repos) |
| Decorator | `backend/repositories/decorators/LoggingRepositoryDecorator.js` |
| Facade | `backend/services/*Service.js` |
| Strategy | `backend/strategies/SortStrategy.js` |
| Observer | `backend/events/ReviewSubject.js` (+ observers) |

OOP throughout: encapsulation (private `#fields`), inheritance, abstraction
(abstract bases), polymorphism (strategies/observers/decorated repos via shared
interfaces). Details + code snippets in `docs/A2/report-section-3.md`.

## Setup & run (local)
**Backend**
```bash
cd backend
cp .env.example .env          # set MONGO_URI and JWT_SECRET
npm install
npm test                      # 49 passing (no DB needed)
npm run seed                  # 6 restaurants, admin + diner, 3 notifications
npm run dev                   # http://localhost:5001  (health: /api/health)
```
**Frontend**
```bash
cd frontend
cp .env.example .env          # REACT_APP_API_URL=http://localhost:5001
npm install
npm start                     # http://localhost:3000
```

## Testing

## CI/CD
`.github/workflows/ci.yml`: Job 1 runs unit tests on every push/PR; Job 2 (push to
`main`) builds the React app, copies it to EC2, and runs **pm2** for both
`mesa-backend` (:5001) and `mesa-frontend` (:3000) behind **nginx** (:80).
Setup: `docs/A2/cicd-runbook.md` + `scripts/ec2-setup.sh`.
